II. Testing Documentation

1. Scope of Testing

The testing scope covers the VietRide React frontend and its integration contracts with VietRide backend APIs. The objective is to verify authentication, role-aware operations, API mapping, idempotent mutations, payment handling, image upload, route processing, and management workflows.

In scope

  • Authentication: login, session persistence, refresh token, logout, operator registration, OTP verification, and password recovery.
  • System Admin: operator/user administration, locations, vouchers, campaigns, plans, reports, RAG, invoices, settlements, and notifications.
  • Operator Admin: vehicles, seat layouts, staff, routes, schedules, trips, bookings, parcels, vouchers, subscription/VNPay, wallet, invoices, and tracking.
  • Operator Staff: permitted operational views for trips, booking, parcel, dispatch, tracking, notifications, and incidents.
  • Cross-cutting: response envelopes, backend errors, idempotency, pagination, Firebase image upload, shared accessibility, Google Places, and encoded polylines.

Out of scope and constraints

  • Backend unit/database tests, production VNPay settlement, email infrastructure, and Firebase infrastructure rules.
  • Automated frontend tests use mocked HTTP responses; staging end-to-end execution is still required.
  • Full visual regression and cross-browser coverage remain manual release-gate activities.

2. Test Strategy

The strategy combines automated unit/component/API-contract tests with manual system and acceptance tests. Highest priority is assigned to authentication, money movement, subscription state transitions, booking/parcel operations, and idempotent mutations.

5.4 Defect and Risk Analysis

  • No automated regression failures were observed.
  • Mocks validate frontend behavior and HTTP contracts but do not prove backend email delivery, VNPay IPN, Firebase rules, or production data consistency.
  • External callbacks and cross-service state synchronization require staging end-to-end evidence.
  • Manual responsive, accessibility, and browser checks remain required for critical journeys.
Conclusion: The frontend automated regression gate is PASSED. Release acceptance remains conditional on staging end-to-end and stakeholder acceptance testing.
